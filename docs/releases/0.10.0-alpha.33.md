# Alpha.33: Matrix widget canvas, layers and coloured emoji

Matrix mode now has **Text**, **Value**, **Clock**, **Pixel art** and **Emoji** add
buttons, a Layers list and contextual widget properties. Every widget has its
own 4-, 5- or 10-dot height, position, width, font, colour and alignment.

Drag a widget anywhere on the 90×10 canvas. Positions snap to individual LEDs
and stay inside the screen. Arrow keys nudge one dot; Shift+arrows move ten.
Escape cancels a drag. Layers support ordering, visibility, locking, duplication
and deletion. Pixel art has an explicit **Paint pixels** tool so dragging can
also move a pixel-art widget. In paint mode, Space paints and Delete erases;
outside paint mode, Delete removes the selected unlocked widget.

Existing panel, column and two-row settings become layers at their previous
positions. Migration retains visible pixels, fonts, alignment and source art,
including hidden art rows and the original settings. Deleting every widget
saves an intentionally blank canvas rather than restoring the old tiles.

Text accepts up to 50 graphemes, including coloured emoji and joined sequences.
Use Windows + . in the message field for the Windows emoji picker. Bitmap
letters retain the approved pixel fonts; emoji use their own colour palette
and are rasterized to the selected dot height. Four- and five-dot emoji are
necessarily coarse; ten dots provide more detail. Imported animated images
still use their first frame.

Widgets are composited in software into one 90×10 RGB picture for the existing
acknowledged HID transport. No firmware or bootloader changes are made.
Saved edits remain drafts until Apply; the layer limit is 64 and renderer
caches remain bounded. Physical Matrix output still needs qualification.
