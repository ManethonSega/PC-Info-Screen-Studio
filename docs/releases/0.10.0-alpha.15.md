# PC Info Screen Studio 0.10.0-alpha.15, portable alpha

Fixes valid H.264 MP4 videos showing VIDEO UNAVAILABLE in alpha.14.

Windows decoders can send an output-format notification after reading video headers, even when frame dimensions stay unchanged. Alpha.14 incorrectly treated every such notification as an unsupported dimension change. The decoder now refreshes and validates RGB32 dimensions and stride before copying the accompanying frame. This fixes the reproduced fragmented 720p High-profile H.264 case while retaining bounded frame allocation and rejection of incompatible output.

The 3.5-inch serial profile remains 3 fps Auto / 5 fps maximum. The 5.2-inch WinUSB profile remains 12 fps Auto / 20 fps maximum, with transfer-time backpressure. Playback stays silent and PC-decoded; native device H.264/SD-card playback is a separate feature.

Export diagnostics now includes decoder stage, stable error code, source/output dimensions, stride, format-notification count and published-frame count. Failed decoders retain those details in recent errors. Reports still exclude media, file names, personal paths and raw exception messages, and are saved locally only.

Exit the previous version from its tray menu, extract the full ZIP into a new folder and run PCInfoScreenStudio.exe. Existing themes and video playback settings remain compatible. Your original H.264 clip does not need conversion for this reproduced format-notification issue.

Validation: a generated fragmented 1280 × 720, 29.97 fps, High-profile/B-frame/BT.709 MP4 reproduced the exact alpha.14 failure on Windows. Corrected playback is checked at USB native size and serial-scaled size, covering colours/orientation, pause, movement, EOF, loop and resource cleanup. The full Windows controller/WPF suite and published EXE/extracted ZIP smoke tests gate publication. No customer media is included in the repository. Physical playback of the supplied customer clip remains for owner confirmation.
