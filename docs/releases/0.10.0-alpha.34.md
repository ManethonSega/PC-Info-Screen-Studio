# Alpha.34: content-fitted Matrix widgets and full sensor selection

Text, clock, value and emoji widgets now fit their width to their actual
rendered pixels. Font, height, text, label and live-reading changes update the
box automatically. Growing content stays inside the 90-column screen, moving
left when needed. Content wider than the screen uses a 90-dot viewport; enable
scrolling to reveal it. Turn off **Fit width to content** for a custom width or
alignment area. Pixel art keeps an editable drawing width. Previous fixed-tile
layouts retain their authored width/alignment during migration; their widgets
can opt into automatic fitting. Existing alpha.33 free widgets fit by default.

Properties now shows a read-only widget-type heading instead of an editable
Name field. Value widgets have **Label before value**, for example `CPU:` gives
`CPU: 42°C`. Labels can include emoji. A separating space is added when the
label does not already end with whitespace. Existing layer names are retained.

Matrix now uses the same live source catalog and selection-safe SourcePicker
control as Info Screen. Search supports multiple terms, opens the result list,
and never erases the current choice when filtering it out. Clear restores the
full list. **Show advanced sensors** shares the existing app preference and
newly discovered sources appear immediately. Saved advanced choices remain
intact before discovery or while hidden from the list.

Readings use their source's real unit and support decimals and textual sources,
including hardware names. Integer high-value alarm thresholds use the source's
units and can exceed 100. Missing readings still block Apply or blank/resume
active sensor output. Provider freshness is checked for the full catalog.

All widgets still compose into one acknowledged 90×10 RGB image. This update
does not alter device firmware or the transport protocol. Physical Matrix
output requires hardware qualification.
